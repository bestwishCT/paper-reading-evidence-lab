47: 2 Multi-Document Question Answering
48: Our goal is to better understand how language
49: models use their input context. To this end, we
50: 1nelsonliu.me/papers/lost-in-the-middle.
51: analyze model performance on multi-document
52: question answering, which requires models to find
53: relevant information within an input context and
54: use it to answer the question. In particular, we
55: make controlled changes to the length of the input
56: context and the position of the relevant informa-
57: tion and measure changes in task performance.
58: 2.1 Experimental Setup
59: In the multi-document question answering task,
60: the model inputs are (i) a question to answer and
61: (ii) k documents (e.g., passages from Wikipedia),
62: where exactly one of the documents contains the
63: answer to the question and k −1 ‘‘distractor’’
64: documents do not. This task requires the model
65: to access the document that contains the answer
66: within its input context and use it to answer the
67: question. Figure 2 presents an example.
68: We instantiate this task with data from
69: NaturalQuestions-Open (Lee et al., 2019;
70: Kwiatkowski et al., 2019), which contains
71: historical queries issued to the Google search
72: engine, coupled with human-annotated answers
73: extracted from Wikipedia. In particular, we take
74: the 2655 queries where the annotated long answer
75: is a paragraph (as opposed to a list or a table).
76: We use passages (chunks of at most 100 tokens)
77: from Wikipedia as documents within our input
78: contexts. For each of the queries, we need a
79: document that contains the answer and
80: k −1
81: distractor documents that do not contain the
82: answer. To obtain a document that answers the
83: question, we use the Wikipedia paragraph that
84: contains the answer from the NaturalQuestions
85: annotations.
86: To collect k −1 distractor documents that do
87: not contain the answer, we use a retrieval system
88: (Contriever, fine-tuned on MS-MARCO; Izacard
89: et al., 2021) to retrieve the k−1 Wikipedia chunks
90: that are most relevant to the query and do not
91: contain any of the NaturalQuestions-annotated
92: answers.

50: 2.3 Results and Discussion
51: We experiment with input contexts containing 10,
52: 20, and 30 total documents. Figure 5 presents
53: multi-document question answering performance
54: when varying the position of relevant information
55: within the input context. To contextualize model
56: performance, we also evaluate on the closed-book
57: and oracle settings (Table 1). In the closed-book
58: setting, models are not given any documents in
59: their input context, and must rely on their paramet-
60: ric memory to generate the correct answer. On the
61: other hand, in the oracle setting, language models
62: are given the single document that contains the
63: answer and must use it to answer the question.

31: 3 How Well Can Language Models
32: Retrieve From Input Contexts?
33: Given that language models struggle to retrieve
34: and use information from the middle of their input
35: contexts in the multi-document question answer-
36: ing task, to what extent can they simply retrieve
37: from input contexts? We study this question with
38: a synthetic key-value retrieval task, which is de-
39: signed to provide a minimal testbed for the basic
40: ability to retrieve matching tokens from an input
41: context.
42: 3.1 Experimental Setup
43: In our synthetic key-value retrieval task, the inputs
44: are (i) a string-serialized JSON object with k
45: key-value pairs, where each of the keys and values
46: are unique, randomly generated UUIDs and (ii) a
47: key within the aforementioned JSON object. The
48: goal is to return the value associated with the
49: specified key. Thus, each JSON object contains
50: one relevant key-value pair (where the value is
51: to be returned), and
52: k −1 irrelevant ‘‘distractor’’
53: key-value pairs. Figure 6 provides an example
54: input context and its corresponding desired output.
55: We again measure accuracy by evaluating whether
56: the correct value appears in the predicted output.
57: Our synthetic key-value retrieval task shares
58: similar goals with the Little Retrieval Test of
59: Papailiopoulos et al. (2023) and the fine-grained
60: line retrieval task of Li et al. (2023), but we ex-
61: plicitly seek to distill and simplify the task by
62: removing as much natural language semantics as
63: possible (using random UUIDs instead), since lan-
64: guage features may present potential confounders.
65: For example, Transformer language models may
66: have varying sensitivity to different linguistic
67: features in their input (O’Connor and Andreas,
68: 2021).
